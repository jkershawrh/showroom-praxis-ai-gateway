= Track 1: Establish the governed gateway

You are the platform engineer for teams that currently copy model credentials into each application. Your first objective is to prove that OpenShift and Praxis—not individual client repositories—own the model-access boundary.

== What you will learn

* Recognize the client, gateway, and backend trust boundaries
* Use a controlled red state to test the recovery contract
* Verify GitOps reconciliation and gateway-owned credentials

== See: The controlled request path

image::architecture.svg[Track 1 request path through Praxis to a configured backend,link=self,window=_blank]

The application sends an OpenAI-compatible request to Praxis. It does not receive the backend URL or backend credential. Praxis selects the configured backend and injects authorization only as the request crosses the gateway boundary.

Publishing House has already created the runtime ConfigMap and Secret from the endpoint and per-order virtual key produced by the RHDP LiteMaaS workload. Argo CD deploys Praxis and an OAuth-protected learner UI without receiving the virtual key as a Helm value.

Praxis is upstream software running on Red Hat OpenShift. The lab does not represent it as a supported Red Hat product. MaaS supplies a replaceable LLM because the demonstration platform shares model capacity across labs.

== Do: Test the deployment contract

=== Step 1: Record the green baseline

[source,bash,role="execute",subs="attributes+"]
----
oc -n {project_name} wait --for=condition=Available deployment/praxis-ai deployment/praxis-ui --timeout=180s
oc -n {project_name} get deployment,service,route,networkpolicy
----

Both deployments should be available, and only the learner UI should have a Route.

=== Step 2: Create a controlled red state

Scale the gateway to zero replicas. This is safe in your single-user environment and makes the availability assertion fail for a known reason.

[source,bash,role="execute",subs="attributes+"]
----
oc -n {project_name} scale deployment/praxis-ai --replicas=0
oc -n {project_name} wait --for=condition=Available deployment/praxis-ai --timeout=10s || echo "RED: gateway unavailable as expected"
----

The timeout and `RED` message prove that the check detects the broken state.

=== Step 3: Observe GitOps recovery

Argo CD self-healing restores the declared replica count. Watch the Deployment return to green.

[source,bash,role="execute",subs="attributes+"]
----
oc -n {project_name} wait --for=condition=Available deployment/praxis-ai --timeout=180s
oc -n {project_name} get deployment praxis-ai -o jsonpath='{.status.availableReplicas}{" available\n"}'
----

If reconciliation takes longer than expected, inspect the application without changing its desired state.

[source,bash,role="execute",subs="attributes+"]
----
oc -n openshift-gitops get application praxis-ai-gateway-{guid}
----

=== Verify

Confirm that the backend credential is a Secret reference rather than a literal environment value.

[source,bash,role="execute",subs="attributes+"]
----
oc -n {project_name} get deployment praxis-ai -o jsonpath='{.spec.template.spec.containers[0].env[0].valueFrom.secretKeyRef.name}{"\n"}'
----

The result must be `model-backend-credentials`. Do not retrieve or print the Secret value.

== Key takeaway

The gateway boundary is an observable, reconciled platform resource. The red/green exercise proves both the availability assertion and GitOps recovery, while the deployment definition proves that application configuration contains only a Secret reference.
